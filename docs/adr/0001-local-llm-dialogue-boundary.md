# Граница подключения локальной языковой модели

Статус: superseded by ADR-0002

Игра подключается к отдельно запущенному сервису локальной языковой модели через OpenAI-compatible HTTP API. Провайдер использует полный ответ без streaming, хранит историю диалога только во время текущего запуска игры и передаёт persona персонажа вместе с каждым запросом. Конфигурация подключения и persona хранятся в редактируемых Godot `Resource`-assets. Такой вариант сохраняет заменяемость Ollama, LM Studio и `llama.cpp`, не требует управлять процессом модели из игры и не отправляет запросы во внешний облачный сервис; при ошибке UI показывает локальную ошибку и позволяет повторить запрос. Сервис доступен из доверенной локальной сети без авторизации.

## Considered Options

- Нативный API конкретного рантайма: проще для одного поставщика, но создаёт ненужную зависимость от него.
- Запуск процесса модели из Godot: удобнее для пользователя в готовой сборке, но усложняет запуск, диагностику и поддержку платформ.
- Streaming в первой версии: улучшает ощущение скорости, но добавляет отмену, обработку частичных ответов и более сложное состояние UI.
- Постоянная память диалога: полезна для долгих сессий, но требует хранения данных, ограничения размера контекста и отдельной политики приватности.

## Consequences

- При запуске игры сервис локальной языковой модели должен быть доступен отдельно и принимать подключения из локальной сети.
- Любое устройство в этой локальной сети может отправлять запросы сервису, пока авторизация не добавлена; сервис нельзя открывать за пределы доверенной сети.
- После перезапуска игры история диалога исчезает.
- UI сохраняет существующую модель состояний `started/received/failed`.
- Позднее можно добавить streaming или постоянную память, не меняя выбранный HTTP-контракт.
- Запрос передаёт persona, затем историю текущего персонажа и в конце новое сообщение игрока.
- История ограничена последними 12 сообщениями и примерно 8000 символами; старые сообщения удаляются целыми парами «игрок + персонаж».
- В первой версии принимается только непустой текст `choices[0].message.content`; tool calls и JSON-ответы не поддерживаются.
- Повторная отправка выполняется только по явному действию игрока, без автоматического retry.
- Адрес сервиса хранится целиком в конфигурационном `Resource`, поэтому может указывать на `localhost` или IP-адрес компьютера в локальной сети.
- Полный текст диалога не записывается в лог по умолчанию; логируются состояния запроса, длительность и технические причины ошибок.

## Module Shape

`ChatResponder` остаётся внешним швом между UI и генерацией ответа. Его интерфейс не раскрывает историю, persona, HTTP или JSON:

- `Main` вызывает `RequestResponse(string message)` и получает сигналы `ResponseStarted`, `ResponseReceived` и `ResponseFailed`.
- `MockChatResponder` остаётся тестовым и автономным адаптером.
- `LocalLlmResponder` становится реальным адаптером и скрывает сборку сообщений, ограничение истории, HTTP-запрос и разбор JSON.
- История хранится внутри конкретного `LocalLlmResponder`, поэтому разные NPC не смешивают свои диалоги.
- `LocalLlmConfig` и `NpcPersona` являются отдельными Godot `Resource`-assets; runtime-история не является `Resource` и не сохраняется на диск.

Внутри `LocalLlmResponder` используются Godot `HTTPRequest` для полного HTTP-запроса и типизированные DTO с `System.Text.Json`. Автоматический retry отсутствует: после ошибки повтор выполняется только новым действием игрока.

## Request Sequence

1. UI проверяет пустой ввод и вызывает `RequestResponse`.
2. Адаптер отклоняет пересекающийся запрос и emits `ResponseStarted` для принятого запроса.
3. Адаптер строит массив сообщений: `system` с persona, затем ограниченная история, затем новое сообщение игрока.
4. Адаптер отправляет `POST` на `{BaseUrl}/chat/completions` с выбранной моделью и параметрами генерации.
5. После ответа адаптер проверяет HTTP-статус, разбирает `choices[0].message.content` и отклоняет пустой текст.
6. Только после успешного ответа адаптер фиксирует пару «сообщение игрока + ответ персонажа» в истории и emits `ResponseReceived`.
7. При timeout, сетевой, HTTP или JSON-ошибке адаптер не меняет историю и emits `ResponseFailed` с понятным сообщением.

## Test Surface

Основной тестовый шов — `ChatResponder`. Для `LocalLlmResponder` внутренний HTTP transport заменяется fake transport, который возвращает заранее подготовленные JSON-ответы и ошибки. Отдельно выполняется ручная smoke-проверка против реально запущенного локального рантайма.
