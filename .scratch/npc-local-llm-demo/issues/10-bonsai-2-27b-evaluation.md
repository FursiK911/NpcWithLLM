# 10: Локальная оценка Bonsai 2 27B

**What to do:** Скачать Bonsai 2 27B и оценить её как альтернативную локальную языковую модель для Ивана по принятому протоколу живого диалога.

**Type:** task

**Status:** ready-for-human

Пользователь поручил подготовить именно проверку этой модели. В рамках выполнения этой задачи разрешено скачать один вариант весов и запустить модель локально для оценки. Последующее отдельное решение пользователя от 2026-09-24 переключает игру на Bonsai по умолчанию (см. ADR-0007); веса по-прежнему не добавляются в Git/Git LFS или поставку.

## Контекст

- На момент оценки действующей моделью игры была `qwen3.5:4b`. Её конфигурацию не переключали в ходе самого оценочного прогона; последующее решение пользователя изменить значение по умолчанию записано в ADR-0007.
- Bonsai 2 27B выпущена PrismML на базе Qwen3.8-27B и опубликована под Apache 2.0. Официальная карточка публикует два подходящих GGUF-пакета: `PQ2_0` (около 6,7 ГиБ весов) и более компактный `PTQ1_0` (около 5,5 ГиБ весов).
- Bonsai 2 хранит веса в специальном формате и требует runtime из форка PrismML. Обычная Ollama не может загрузить эти пакеты. Игра и существующий runtime используют Ollama `/api/chat`; тестовый harness также разбирает поток Ollama.
- Для NPC с текстовым диалогом vision projector не нужен. Целевая сборка игры ориентируется на 8 ГБ VRAM; предыдущие оценки на этой машине проводились на RTX 4070 Ti с 12 ГБ, что само по себе не подтверждает работу на 8 ГБ.
- Источники: [карточка и память Bonsai 2 GGUF](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf), [официальные Windows-инструкции PrismML](https://github.com/PrismML-Eng/Bonsai-demo), [бюджет рассуждений и настройки рантайма](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/AGENTS.md), [статус поддержки формата в Ollama](https://github.com/ollama/ollama/issues/18521).

## Требования

- [x] Перед загрузкой проверить текущие официальные Windows-инструкции PrismML и выбрать их совместимый runtime. Использовать опубликованный PrismML runtime, а не пытаться импортировать Bonsai 2 через Ollama.
- [x] Для RTX 4070 Ti выбрать `PTQ1_0`, если текущая документация PrismML подтверждает эту сборку для Windows/CUDA. Она меньше `PQ2_0` и заявлена как подходящая для Ada. Если она недоступна или не запускается, записать причину и только тогда рассмотреть официальный `PQ2_0`.
- [x] Загружать только необходимые для текстового диалога веса. Не скачивать vision projector и не помещать большие файлы модели в репозиторий или Git LFS. Зафиксировать точный URL/идентификатор, имя файла, лицензию, размер и SHA-256.
- [x] Запустить сервис локально на `127.0.0.1`. Проверить, что запросы и текст диалога не уходят во внешний сервис.
- [x] Подключить оценочный запуск к PrismML через отдельный тестовый адаптер `ILocalLlmRuntime` или эквивалентный transport. Сохранить игровой `LocalLlmResponder`, профиль `NpcProfile.tres`, `ContextBuilder`, память и историю. Использовать существующий seam `LocalLlmResponder.Configure(...)`; не менять Ollama runtime и конфигурацию игры ради этого прогона. Адаптер должен разбирать поток OpenAI-compatible SSE и брать только видимый текст ответа.
- [x] Учесть, что Bonsai 2 включает рассуждения по умолчанию. Передавать бюджет рассуждений `0` (или эквивалентную настройку PrismML), чтобы оценивать видимый ответ персонажа в режиме, сопоставимом с `think: false` игры. Не сохранять скрытый канал рассуждений в транскрипт.
- [x] Провести один адаптивный свободный диалог из 32 реплик игрока. Каждую следующую реплику выбирать после чтения ответа Ивана; заранее подготовленный список реплик не использовать. Использовать текущие профиль, настройки генерации, контекст, память и историю игры. Не добавлять отдельный текст роли или подсказки для кандидата.
- [x] Человек оценивает ответы по шкале 1–10 с примерами: сохранение личности и роли; связность; уместность; фактическая аккуратность и реакция на неизвестное; грамотность русского языка; естественность и манера речи; память; повторы и поддержание беседы. Автоматические проверки оценивают только транспортные сбои.
- [x] Записать точную версию runtime и параметры генерации, время подготовки/прогрева, задержку до первого видимого текста и полного ответа, фактическое использование VRAM и сведения о машине. Это замеры, без числового порога пригодности. Отдельно указать, что тест на 12 ГБ не доказывает пригодность для целевой машины с 8 ГБ.
- [x] Сохранить полный диалог, оценки и аргументированную рекомендацию в `../reports/10-bonsai-2-27b-evaluation.md`. Сравнить наблюдения прежде всего с `../reports/06-live-dialogue-model-evaluation.md` и, если уместно, с `../reports/06-qwen3-4b-instruct-evaluation.md`; отметить различия условий.
- [x] После прогона завершить только процесс PrismML runtime, запущенный этой задачей. Не завершать существующие пользовательские процессы.
- [x] Если используется существующий `Tests/LiveDialogueEvaluationRunner.cs`, не перезаписывать результаты или параметры прогона Gemma 4; сохранить отдельные настройки и пути для Bonsai 2.
- [x] На время исходной оценки оставить `qwen3.5:4b` моделью по умолчанию, не включая Bonsai в поставку. Это условие позднее заменено решением пользователя переключить провайдер по умолчанию; веса и Prism runtime остаются внешними.

## Готово, когда

Отчёт содержит воспроизводимые сведения о модели и runtime, полный адаптивный диалог, ручные оценки с примерами, фактические замеры производительности и VRAM, ограничения проверки и рекомендацию. Если официальный runtime или веса не удаётся запустить, отчёт фиксирует выполненные шаги и точную ошибку; альтернативная модель автоматически не подставляется.
