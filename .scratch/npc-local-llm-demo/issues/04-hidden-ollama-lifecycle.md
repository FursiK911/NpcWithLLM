# 04: Скрытый жизненный цикл Ollama

**What to build:** Игра подключается к уже работающему локальному Ollama или незаметно запускает свой экземпляр и закрывает только процесс, которым владеет.

**Blocked by:** 03: Настоящий ответ локальной LLM

**Status:** ready-for-human
**Resolution:** confirmed

- [x] Перед запуском bundled Ollama CLI проверяется его ожидаемый SHA-256.
- [x] Если endpoint `127.0.0.1:11434` уже отвечает, игра использует его и не запускает второй экземпляр.
- [x] Если endpoint недоступен, игра запускает bundled Ollama CLI без видимого консольного окна.
- [x] Игра различает внешний и собственный процесс Ollama и завершает только собственный при выходе или неудачной подготовке.
- [x] Ошибка запуска или подключения доступна интерфейсу как диагностируемое состояние; mock-ответчик не подменяет локальную модель.
- [ ] Ручной Windows-smoke подтверждает повторное использование внешнего endpoint и скрытый запуск собственного процесса.

## Comments

- Реализация уже присутствует в `f6600a4` (`feat: manage hidden Ollama lifecycle`): `OllamaServerController` проверяет SHA-256 перед запуском, повторно использует loopback endpoint, запускает CLI скрыто и останавливает только принадлежащий ему процесс. `LocalLlmRuntime` передаёт диагностируемые ошибки через `LocalLlmResponder`; автоматического mock-fallback нет.
- Windows-smoke описан в `README.md` и реализован в `Tests/OllamaLifecycleSmoke.ps1`. Он не запускался в рамках этой задачи. В исходном checkout bundled `tools/ollama/ollama.exe` отсутствует; README указывает, что бинарник добавляется Windows-поставкой.
