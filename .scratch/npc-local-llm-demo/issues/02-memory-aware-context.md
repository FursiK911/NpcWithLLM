# 02: Память персонажа и ограниченный контекст

**What to build:** NPC использует отдельную память персонажа и ограниченный контекст, чтобы сведения из одного сообщения влияли на последующие ответы.

**Blocked by:** 01: Играбельная 2D-сцена диалога

**Status:** ready-for-agent

- [ ] Persona NPC задаёт имя, роль, характер, стиль речи, отношение к игроку и ограничения поведения.
- [ ] Память персонажа отделена от истории диалога.
- [ ] Из русских явных сообщений извлекаются как минимум имя игрока и его профессия.
- [ ] Память существует только в текущей сессии игры.
- [ ] Context Builder передаёт persona, состояние, факты памяти, ограниченную историю и новую реплику в согласованном порядке.
- [ ] История ограничена последними 12 сообщениями и примерно 8000 символами.
- [ ] История удаляется целыми парами «игрок + персонаж».
- [ ] Новая пара добавляется в память и историю только после успешного ответа.
- [ ] Ошибочный или пустой ответ не изменяет память и историю.
- [ ] Разные экземпляры персонажа не разделяют runtime-память.
- [ ] Fake runtime позволяет проверить сформированный контекст без реальной модели.
- [ ] Сценарий «Меня зовут Алекс. Я механик» → последующий вопрос о профессии подтверждает использование памяти.
