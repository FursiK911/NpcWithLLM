# 02: Память персонажа и ограниченный контекст

**What to build:** NPC использует отдельную память персонажа и ограниченный контекст, чтобы сведения из одного сообщения влияли на последующие ответы.

**Blocked by:** 01: Играбельная 2D-сцена диалога

**Status:** ready-for-human

- [x] Persona NPC задаёт имя, роль, характер, стиль речи, отношение к игроку и ограничения поведения.
- [x] Память персонажа отделена от истории диалога.
- [x] Из русских явных сообщений извлекаются как минимум имя игрока и его профессия.
- [x] Память существует только в текущей сессии игры.
- [x] Context Builder передаёт persona, состояние, факты памяти, ограниченную историю и новую реплику в согласованном порядке.
- [x] История ограничена последними 12 сообщениями и примерно 8000 символами.
- [x] История удаляется целыми парами «игрок + персонаж».
- [x] Новая пара добавляется в память и историю только после успешного ответа.
- [x] Ошибочный или пустой ответ не изменяет память и историю.
- [x] Разные экземпляры персонажа не разделяют runtime-память.
- [x] Fake runtime позволяет проверить сформированный контекст без реальной модели.
- [x] Сценарий «Меня зовут Алекс. Я механик» → последующий вопрос о профессии подтверждает использование памяти.

## Comments

Реализованы `NpcPersona`, `NpcMemory`, `DialogueHistory`, `ContextBuilder`, `LocalLlmResponder`, `ILocalLlmRuntime` и `FakeLocalLlmRuntime`. Выполнены сборка, ручные поведенческие проверки извлечения фактов, порядка контекста, лимитов истории и неизменности состояния при пустых данных. Подключение production Ollama остаётся в issue 03/04.

2026-09-23, ADR-0005: два пункта выше устарели. Персона дополнена границами знаний (седьмое поле), а
текст роли вместе с ситуацией переехал в `NpcProfile.tres` — править его в коде больше нельзя. Лимит
истории поднялся с 12 сообщений до 32, и оба предела (сообщения и символы) задаются в
`LocalLlmConfig`; усечение покрывает тест в `Tests/DialogueRegression.Tests.ps1`.
