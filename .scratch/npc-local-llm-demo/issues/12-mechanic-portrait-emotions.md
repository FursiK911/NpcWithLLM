# 12: Портреты механика и эмоции ответов

**What to build:** Заменить геометрическую заглушку механика и временный фон готовыми изображениями; показывать подходящую позу по состоянию диалога и эмоции структурированного ответа.

**Status:** ready-for-human

## Требования

- [x] Фон сцены использует предоставленное изображение мастерской и занимает весь viewport.
- [x] Вместо геометрической заглушки отображается прозрачный спрайт механика; стартовая поза — idle.
- [x] Стартовая панель ответа пуста, пока персонаж не ответил.
- [x] Пока локальная модель готовит ответ, отображается thinking-поза.
- [x] Модель возвращает полный JSON-объект с текстом реплики в поле message и эмоцией в поле emotion.
- [x] Поддерживаемые значения emotion: angry, happy, sad, thinking, neutral.
- [x] Эмоции angry, happy, sad и thinking соответствуют одноимённым портретам. Значение neutral, пропущенное или неизвестное значение выбирает случайный портрет speak_1–speak_5.
- [x] Ответ персонажа отображается после получения и разбора полного JSON; в панели и истории диалога используется только текст message.
- [x] После успешного ответа выбранный портрет остаётся видимым до следующего запроса.
- [x] Невалидный JSON или отсутствующее/пустое поле message считается ошибкой: прежние текст ответа и портрет не меняются, а сообщение игрока остаётся для повтора.
- [x] Внешнее поведение проверяется в существующем DialogueSmoke через основную сцену и управляемый fake runtime; отдельный UI-test framework не вводится.

## Контекст

Это уточнение вертикального среза локального NPC-диалога. Использовать термины проекта: персонаж, ответ персонажа, сообщение игрока и профиль персонажа. Эмоция ответа описывает его настроение и не добавляет модели новых фактов о сцене.
