# 05: Проверка и подготовка выбранной модели

**What to build:** Перед диалогом игра проверяет, что модель из `LocalLlmConfig.ModelName` установлена в локальной Ollama, и прогревает её. Игровая конфигурация по умолчанию использует `qwen35-9b-q4km-bartowski:local` согласно ADR-0009.

**Blocked by:** 04: Скрытый жизненный цикл Ollama

**Status:** ready-for-human

## Решение

- Имя используемой модели берётся из `LocalLlmConfig.ModelName`; runtime не закрепляет имя модели в коде.
- Пользователь заранее устанавливает или импортирует модель в локальную Ollama. Веса остаются вне репозитория и ZIP-поставки согласно [ADR-0009](../../../docs/adr/0009-qwen35-9b-default.md).
- Игра не скачивает модель, не вызывает `ollama pull`, не импортирует GGUF и не изменяет установленные модели. Для модели не требуется checksum: она не распространяется проектом.
- Этот тикет отвечает за наличие и готовность модели после подготовки сервиса Ollama из тикета #04. Проверку, отображение этапов и блокировку ввода в игровой сцене описывает тикет #07.

## Требования

- [x] До сообщения о готовности runtime проверяет в локальной Ollama наличие точного значения `LocalLlmConfig.ModelName`.
- [x] Отсутствующая модель даёт отдельную диагностируемую ошибку с именем запрошенной модели и указанием установить её в локальную Ollama.
- [x] Ошибка отсутствующей модели отличается от недоступности сервиса Ollama и от ошибки генерации.
- [x] После проверки модель прогревается коротким запросом с настроенным пределом контекста. Runtime сообщает о готовности только после успешного завершения прогрева.
- [x] Прогрев не добавляет реплики в историю диалога, не меняет память персонажа и не показывает пробный текст игроку.
- [x] Ошибка подготовки не включает mock-ответчик; UI не разрешает начать диалог до успешной подготовки.
- [x] Установленная модель подготавливается через loopback-сервис Ollama без доступа к внешней сети.
- [x] Автоматические проверки используют fake HTTP-ответы и покрывают: установленную модель с настраиваемым именем, отсутствующую модель, отдельные ошибки сервиса и генерации, успешный прогрев и отказ при неуспешном прогреве. Проверки подтверждают, что runtime не инициирует загрузку модели.

## Готово, когда

`PrepareAsync` подтверждает наличие настроенной модели и завершает её прогрев до события готовности; при отсутствии модели или сбое подготовки возвращает соответствующую ошибку без изменения локальной установки, истории, памяти или mock-fallback. Автоматические проверки покрывают оба исхода.
