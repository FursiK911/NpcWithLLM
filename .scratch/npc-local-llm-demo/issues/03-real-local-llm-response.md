# 03: Настоящий ответ локальной LLM

**What to build:** Игра получает настоящий ответ от локально работающего Ollama через `LocalLlmRuntime`, не раскрывая детали runtime игровому UI.

**Blocked by:** 02: Память персонажа и ограниченный контекст

**Status:** ready-for-agent

- [x] Настройки подключения, имя модели, timeout и параметры генерации редактируются без изменения UI-логики.
- [x] `LocalLlmResponder` реализует тот же lifecycle, что и mock-ответчик.
- [x] Запрос содержит persona, состояние, память, ограниченную историю и текущую реплику.
- [x] Успешный непустой ответ локальной модели отображается в UI.
- [x] Полный ответ обрабатывается без streaming.
- [x] HTTP error, network error, timeout, некорректный JSON и пустой ответ превращаются в понятную ошибку UI.
- [x] Технические детали ошибки пишутся в debug log без полного текста диалога.
- [x] Второй запрос во время активного запроса отклоняется.
- [x] Ошибка не добавляет сообщение в историю и не стирает ввод игрока.
- [x] Fake runtime покрывает успешный ответ и основные классы ошибок.
- [ ] Ручной запуск подготовленного Ollama подтверждает реальный end-to-end ответ в сцене.

## Comments

Добавлен production `LocalLlmRuntime` для локального Ollama HTTP API, редактируемый `LocalLlmConfig`,
типизированные пользовательские ошибки и расширенный fake runtime. Ручная проверка реального Ollama
проведена на `gemma3:270m`: endpoint вернул непустой ответ с `done=true`. UI-smoke через окно Godot
не завершён, потому что окно запуска не было доступно для Computer Use; этот последний пункт требует
ручного ввода в сцене.
