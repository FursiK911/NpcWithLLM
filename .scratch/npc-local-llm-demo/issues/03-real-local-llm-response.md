# 03: Настоящий ответ локальной LLM

**What to build:** Игра получает настоящий ответ от локально работающего Ollama через `LocalLlmRuntime`, не раскрывая детали runtime игровому UI.

**Blocked by:** 02: Память персонажа и ограниченный контекст

**Status:** ready-for-agent

- [x] Настройки подключения, имя модели, timeout и параметры генерации редактируются без изменения UI-логики.
- [x] `LocalLlmResponder` реализует тот же lifecycle, что и mock-ответчик.
- [x] Запрос содержит persona, состояние, память, ограниченную историю и текущую реплику.
- [x] Успешный непустой ответ локальной модели отображается в UI.
- [x] Полный ответ обрабатывается без streaming.
- [x] HTTP error, network error, timeout, некорректный JSON и пустой ответ превращаются в понятную ошибку UI.
- [x] Технические детали ошибки пишутся в debug log без полного текста диалога.
- [x] Второй запрос во время активного запроса отклоняется.
- [x] Ошибка не добавляет сообщение в историю и не стирает ввод игрока.
- [x] Fake runtime покрывает успешный ответ и основные классы ошибок.
- [ ] Ручной запуск подготовленного Ollama подтверждает реальный end-to-end ответ в сцене.

## Comments

Добавлен production `LocalLlmRuntime` для локального Ollama HTTP API, редактируемый `LocalLlmConfig`,
типизированные пользовательские ошибки и расширенный fake runtime. Ручная проверка реального Ollama
проведена на `gemma3:270m`: endpoint вернул непустой ответ с `done=true`. UI-smoke через окно Godot
не завершён, потому что окно запуска не было доступно для Computer Use; этот последний пункт требует
ручного ввода в сцене.

После ручного smoke-теста обнаружено, что `gemma3:270m` не использовала системные сообщения из
массива `messages`, поэтому память игрока терялась в запросе. Системный контекст теперь переносится
в поле `system`, а вопросы о фактах игрока получают компактную подсказку в последнем сообщении.
Добавлены regression tests для `LocalLlmRequestBuilder` и `ContextBuilder`. Полный последовательный
сценарий через реальный Ollama прошёл: ответ на вопрос о Дмитрии и профессии содержит оба факта.
Ручная проверка именно через окно Godot остаётся обязательной перед сменой статуса тикета.

После выбора Qwen3.5 0.8B конфигурация, regression test и запрос к Ollama переведены на
`qwen3.5:0.8b`. Для этой модели явно передаётся `think: false`, чтобы reasoning не попадал в
видимый ответ. API-проверка на Qwen подтвердила формат ответа с именем и профессией игрока, а
вопросы `Кто ты?` и `А ты кто?` возвращают имя и роль Ивана. Свободные реплики всё ещё могут
потребовать ручной проверки качества маленькой модели; end-to-end проверка через окно Godot
остаётся обязательной.

Дополнительно ручная проверка выявила вопрос «Кто ты?», на который модель отвечала, что она большая
языковая модель. На промежуточном этапе `ContextBuilder` добавлял имя и роль персонажа в компактную
подсказку для вопросов об идентичности NPC; это помогало диагностировать transport и memory-баги,
но не соответствовало цели свободного диалога.

Для реплики `Привет, я Дмитрий. А тебя как зовут?` найден и исправлен отдельный дефект
распознавания: шаблон знал `как тебя зовут`, но не естественный порядок слов `тебя как зовут`.
Добавлен regression test и повторена реальная проверка через Ollama; ответ теперь содержит имя и
роль NPC вместо свободного описания мастерской.

По решению пользователя специальные question-шаблоны и форматированные подсказки удалены.
`ContextBuilder` теперь передаёт новую реплику игрока без переписывания, а в системном контексте
оставляет только персону, неизменную идентичность, общие правила поведения, состояние сцены и
память. Регрессионные тесты проверяют именно это разделение.

Проверка на `qwen3.5:0.8b` показала, что после удаления шаблонов маленькая модель всё ещё может
выдумывать имя или называть себя ИИ. Это ограничение качества выбранной модели, а не скрытая
логика формирования ответа; для естественного roleplay потребуется более сильная модель либо
отдельное решение для контроля идентичности.
